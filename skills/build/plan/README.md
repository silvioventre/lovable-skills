# plan

Works out what to build before any of it is written. Explores an unfamiliar project, compares approaches when the decision is hard to reverse, and breaks a vague request into increments that can each be built and checked on their own.

## Install

In Lovable: **Settings → Skills → Add → Import from GitHub**, and paste:

```
https://github.com/silvioventre/lovable-skills/tree/main/skills/build/plan
```

## Use

```
/plan I want to add comments and likes — what am I signing up for?
/plan explore this project and explain how it works, I haven't touched it in months
/plan what's the best way to handle real-time notifications here?
```

Or just describe the situation — the description is written to match how people actually phrase it.

## What's inside

| File | Contents |
|---|---|
| `SKILL.md` | Routing, the no-code-during-planning rule, subagent delegation, and what a finished plan must contain |
| `reference/investigate.md` | Reading an existing project: which questions to ask in parallel, how to brief them, how to read the findings critically |
| `reference/approach.md` | When a decision is worth comparing options over, and how to make the options genuinely different |
| `reference/scope.md` | Turning a request into bricks, naming what it touches, and handing a brick to the build |

## Scope

Not design direction — that is [art-direction](../../design-and-ux/art-direction/). Not diagnosis: if something is broken and the cause is unknown, use [debug](../../troubleshooting/debug/) first, because planning around an un-diagnosed bug is planning around a guess.
